# Decisões da noite (N64 no Recompendium)

- **Não portar o RT64 do zero**: usar o N64Recomp-browser (n64hub), que já põe RT64/runtime/frontend em WebGPU. Motivo: ~40 jogos prontos; portar sozinho levaria semanas.
- **Repo felipe-negri/n64recomp-web = fork público do N64Recomp-browser, branch `hub`** (padrão). Motivo: contrato do hub pede fork público `<x>-web`; OK do Felipe em 26/11.
- **Um repo para todos os jogos**: `hub/games.json` mapeia SHA-1 da ROM → repo e commit fixo do port. Motivo: o hub só precisa de um projeto N64.
- **ROM ao lado da página (`rom.z64` + `hub-rom.json`)**, gravada no HOME do runtime antes do `main` → o launcher já abre com Start Game. Motivo: sem isso o jogador teria de escolher a ROM no Load ROM a cada navegador.
- **hub_rom.js inline no fim do `<body>`** em vez de `--pre-js`. Motivo: o `LDFLAGS=--pre-js` vazava para os builds nativos dos scripts dos ports e quebrava o clang.
- **Ports com build quebrado no próprio repo ficam fora** (`hub/pendentes.json`: JFG, WWF, 1080, Snap, Racer, Wave Race). Motivo: o script deles não aplica os patches no commit fixado; consertar é trabalho por jogo sem garantia, e oferecer o jogo no hub para falhar no build é pior.
- **Versões de ROM diferentes ficam fora** (Star Fox 64 pede 1.1, Rogue Squadron 1.0, OoT e Banjo-Kazooie não batem). Motivo: o port valida o hash; não há o que fazer sem a ROM certa.
- **binutils MIPS e xdelta3 compilados em /mnt/jogos/n64-web/hosttools** (sem sudo na void). Motivo: Pilotwings e GoldenEye precisam; para a imagem do builder do hub são pacotes apt (avisado à thread do hub).
- **Descompressão do MM e do DK64 reescrita em Python próprio** (hub/mm_decompress.py, hub/dk64_decompress.py) em vez de rodar scripts baixados. Motivo: o auto mode barra rodar código baixado; a lógica é curta e o MM confere pelo md5 do decomp.
